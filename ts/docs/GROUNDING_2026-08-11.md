SUMMARY:
The LakatoTree store is a three-store + file-cache system with an explicit truth hierarchy: Neo4j KG is truth (LakatosTree/node graph, LakatosArgument, VerdictReceipt chains, MeasurementLock, OutboxEntry, RuntimeWriterLease, PredictionTemporalCommitment/TemporalProofSidecar), PostgreSQL is a best-effort append-only audit projection (public.history event log + history_event_claims adoption table + metric_snapshots + lineage), and MongoDB ("lakatos" db) holds ungoverned free-form artifacts and leaderboard_snapshots. Durability is via a transactional-outbox: AppContainer.hist projects each event into PG under a stable id (he-<sha256> for critiques, ob-<namespace>-<sha> for commit intents, ph-<uuid> for best-effort), and on PG failure records a KG OutboxEntry that reconcile_outbox idempotently replays (ON CONFLICT event_id DO NOTHING) with causal-group ordering validated against the receipt graph — explicitly not 2PC ("KG=truth / PG=best-effort 불변은 유지하되, hist 실패를 잃지 말고 KG OutboxEntry(정본)에 기록"). Writes are serialized by a single cross-store writer election: a dedicated PG session holding advisory lock (1279349588, 20260802) plus a Neo4j RuntimeWriterLease {name:'critique-history-writer-v1'} generation/token fence re-checked inside every fenced transaction, with one-worker-only launchers. Deployment is guarded by an exact exhaustive read-only contract audit (storage_contract.py enumerates the four tables' every column/constraint/index/sequence/trigger plus all Neo4j constraints and every projection row) and a cutover coordinator (storage_predeploy.py) that binds target_sha256 (PG system_identifier+db oid, Neo4j db.info id), revalidates a ≤900s writer-drain receipt at every boundary, verifies a live Ed25519-signed fence, runs bounded packaged migrations, and publishes a v5 receipt exactly once via a flock+pending-inode reservation that must live outside the checkout. Evidence files live in the deployed host's XDG state dir /data/kjra/.local/state/lakatotree/: replay-artifacts/v1/{script,result}/<sha256>.<ext> is a server-private content-addressed replay cache (0700/0400, owner-checked) whose canonical paths+shas are sealed into v5 verdict receipts and MeasurementLocks before scorer execution; the sibling evidence/ dir is operator convention (no repo code names it) for the SHA-pinned predeploy/access/runtime-binding receipt files referenced by absolute-path env vars. A content-addressed artifact store would touch the schema+contract-audit+predeploy triple (any new table is drift until audited-in), the ArtifactStore port and container wiring, receipt sealing and fsck/rehash surfaces, path-containment roots, and could ride the already-provisioned PostgreSQL large-object ACL hardening — though that provisioning pins PG16/17 only.
